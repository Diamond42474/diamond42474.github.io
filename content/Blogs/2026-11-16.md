# Finally Another Step
As you can tell by the last time I wrote one of these, it's been a while. Just as it is for everyone, life is busy. This last week I was finally able to make some meaningful progress however with [[peregrine-constellation|Peregrine Constellation]]. 

Lately I've been messing around a little bit with locally run LLMs (large language models) mostly because the work I do requires that no data can be exported to external servers. I'm of course a fan of open source projects, so I decided to take a look at [Hermes Agent](https://github.com/nousresearch/hermes-agent). I was quickly impressed by the tasks it was able to accomplish with such a small amount of processing power. After figuring out how it works, I decided to give it a shot helping with the whole [Raw ADC Stream](https://github.com/Diamond42474/pico-constellation/issues/35) thing that's been on my todo list. I tried Codex a while ago and I simply wasn't very pleased with where it got me (see [[2026-08-23|Sync or Sink]] for a little more background). It created a pretty messy large complex file that I kept having to debug. Now I'm sure there's a way to set it up right that works a lot better for people but it just didn't go very well for me. Fast forward to implementing Hermes and I was much happier with the results. I was able to get a nice and simple ADC stream running to my desktop computer with a [Python script](https://github.com/Diamond42474/pico-constellation/tree/master/scripts/recorder) running a GUI so that I can easily visualize and record raw samples. Getting this out of the way gave me a good amount of re-energizing because now instead of flashing the Pico every time I want to try a tweak in the software, I can simply use pre-recorded data and run it through on the host. I was doing this a little bit before, but I didn't have a solidified way to run the whole process; now I do. 

Now, before we get crazy, I do NOT have any intention on having Hermes or AI in general write large chunks of the actual Peregrine Constellation framework. I tried it early on and realized that I want to be in complete control over how this thing operates and know the ins and outs of how it functions. I am totally for having it write functions, do research, run through different unit tests possibilities, but as for "vibe coding", completely out of the question. That is, when it comes to Peregrine Constellation (and mostly Pico Constellation). The helper scripts, such as the Python recorder GUI, totally for having AI write it. That's something that's not at the core of Peregrine Constellation and doesn't hold the same level of importance when it comes to code ownership. 
TL;DR, love using AI to help speed up writing functions, but architectural, operational, and code design are going to stick with us, the users. 

I know it's been a long time since my last post. Hopefully with some of the business of life being over now I should be able to pick up the pace at least a little bit. Until next time.
